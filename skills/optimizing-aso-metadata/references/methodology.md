# ASO Methodology

This reference captures the working model behind this skill.

## Core idea

ASO metadata optimization is not keyword stuffing. It is the process of making the store more confident about:

- what problem the app solves
- which search intents it is relevant to
- why a user should install it

The strongest metadata usually improves three things at once:

1. coverage of real user language
2. structural emphasis on the app's main use cases
3. semantic consistency across title, short text, full text, screenshots, and update notes

## Practical workflow

### 1. Expand the term universe

Start from:

- the app's actual features
- user jobs-to-be-done
- pain-point phrasing
- scenario phrasing
- competitor language

### 2. Clean and classify

Remove:

- irrelevant traffic bait
- terms that overstate functionality
- terms that imply unsupported privacy or security guarantees
- duplicate or near-duplicate variants that create noise

Then classify into:

- direct intent
- related capability
- scenario/long-tail
- risky or blocked

### 3. Plan the metadata map

Decide where each term family belongs:

- title / app name
- subtitle / short description
- full description
- screenshots and overlays
- update notes

### 4. Draft and review

Draft multiple versions only after the plan exists.

Review each version for:

- natural coverage
- readability
- promise clarity
- proof alignment
- policy risk

## Model from the local ASO project

The local project that seeded this skill reported:

- keyword coverage growth from `400` to `1600`
- search-driven organic installs up `13%`
- a supporting conversion example of `6,934` visitors, `4,376` installs, and `63.11%` conversion rate

Treat those as directional evidence for the workflow, not as universal benchmark targets.
